> 交付日期:2026-11-26 · 验收环境 Ascend950DT · 结论:**功能 / 性能 / 精度三项验收全部通过,动态 Shape 需求(R1–R3)闭环**

## 1. 算子概述

生成式推荐推理中的自定义掩码 Flash Attention:输入为 ragged 变长序列,叠加分页 KV cache 与分段规则(segment rules)掩码。本实现为 A5 平台移植自 A3 TileLang 基线。

**接口**:

```python
mtgr_ragged_segment_attention(
    query, key, value,
    segment_offsets_i32, segment_rules_i32, q_seq_starts_i32,
    matched_prefix_lens_i32, match_mode,
    key_cache, value_cache, block_table_i32,
    block_size, max_request_len, sm_scale, output_snd,
    block_M=128, core_num=32, num_stages=14, kv_group=...,
    cross_interval=2, rule1_seg_idx=...,
    *, metadata=..., l2_budget=...,
)
```

统一约束:BF16、查询头 H=8、头维 D∈{32,64,128}、GQA `kv_group`∈{1,2,4,8}、`block_size` 固定 128、`match_mode`∈{0,1,2};索引/页表/分段类输入均为 INT32。

| 张量 | dtype | shape | 说明 |
|---|---|---|---|
| query | BF16 | `[total_q, 8, D]` | 实时查询,`total_q` 为动态维 |
| key / value | BF16 | `[total_q, kv_heads, D]` | 实时 KV,`kv_heads` 运行期推导 |
| key_cache / value_cache | BF16 | `[cache_blocks, 128, kv_heads, D]` | 分页 KV 缓存 |
| block_table | INT32 | `[batch, table_cols]` | 页表,按请求与逻辑页号索引物理页 |
| segment_offsets | INT32 | `[batch, segments+1]` | 每请求分段边界 |
| segment_rules | INT32 | `[segments]` | 每段掩码规则 |
| q_seq_starts | INT32 | `[batch+1]` | 各请求在实时 Q/K/V 中的起止偏移 |
| matched_prefix_lens | INT32 | `[batch]` | 各请求命中的分页缓存前缀长度 |
| output_snd | BF16 | 同 query | 调用方分配,原地更新 |

**执行流程**:独立 AICPU metadata 预处理(设备侧分核计划)→ attention 主 kernel 一次 launch。ACLNN executor 可在 `metadata=None` 时自动编排"独立 AICPU metadata 任务 → attention 主 kernel",调用方无需另行预处理。

**动态维**:五个 ragged 维(`total_q` / `batch` / `num_blocks` / `max_blocks` / `max_segs`)、`kv_heads` 及 `core_num` 全部运行期化;编译产物按 `D=32/64/128` 三种特化,每种特化覆盖全部形状、GQA 与核数,形状变化不再触发重编译。

**实现方式**:cannbot-dsl(Cube 主 kernel)。本轮同步后续 Vector/缓冲优化:D128 QK 三槽 + 独立 PV 单槽、PV 行跨度 136,以及共享 prefix 掩码外提与 64 列半块特化。

## 7. 动态 Shape 需求闭环(R1–R3)

逐条对照同目录 `cannbot-dsl-dynamic-shape-requirement.md`:

- **R1 ✅ 五个 ragged 维 `Dim` 化**:五维分别声明为 `total = Dim("total_q", min=1)`、`batch = Dim("batch", min=1, max=MAX_REQUESTS)`、`segments`、`cache_blocks`、`table_cols`(`src/mtgr_ragged_segment_attention.py:2691-2695`),全部 TensorSpec 使用这些 Dim(`:2698-2712`);编译缓存 key 收敛为 `(head_dimension, query_tile_rows, key_tile_columns)`(`:2675-2680`),形状不再触发重编。一次编译跑通需求文档第 2 节 7 种形状(动态 Shape 验证报告 17/17 + 泛化 10000 覆盖 `total_q` 308~32104+)。
- **R2 ✅ 等价运行时 kv_heads 方案**:`kv_heads = Dim("kv_heads", min=1, max=QUERY_HEAD_COUNT)`(`:2696`)进入 KV/cache spec(`:2701-2705`);`group` 运行期由张量形状推导(`:2448`,kernel 侧 `:1979-1984` 与 `HEADER_GQA_GROUP` 交叉校验)。GQA 1/2/4/8 复用同一产物(`test_dynamic_shape.py:30-37` 断言 compile 调用数=1;精度泛化 kv_group 1/2/4/8 各约 2500 组设备实测)。
- **R3 ✅ metadata 固定上界容量,`core_num` 纯运行期**:`METADATA_CORE_CAPACITY=36` 固定上界(`mtgr_ragged_segment_attention_common.py:15`);metadata 长度 = `METADATA_HEADER_WORDS + batch × kv_heads × 36 × CORE_METADATA_WORDS`(spec 下界 `mtgr_ragged_segment_attention.py:2697`,分配 `mtgr_ragged_segment_attention_metadata.py:525-527`);host `validate_metadata` 按固定上界精确校验(`:2537-2543`);`cores` 移出编译缓存 key;实际核数仅体现于运行期 stride 与 `HEADER_CORE_COUNT`(`mtgr_ragged_segment_attention_metadata.py:278-280,379`;主 kernel `:1981,2005-2006`)。cores 8/16/28/32 × kv_heads 1/2/4/8 host 回归通过,且旧长度 fail-loud(`test_dynamic_shape.py:42-53`)。

需求文档 R1(P0)/R2(P1)/R3(P1)全部闭环,实现路径为 `cannbotdsl.Dim` 原语(0.8.3),非 host workaround。

## 8. 已知限制与集成建议

1. **Host 提交开销**:Python DSL 入口逐次调用 host 开销较大,端到端建议走 ACLNN C API(runtime 运行包)或图捕获;交付仓库 `runtime/mtgr_runtime_ascend950.tar.gz` 不入 git,由源仓库说明获取。
2. **编译变体**:`D=32/64/128` 三种特化(`head_dimension` 为编译期常量,业务上固定);每种首次 JIT 编译后进程内缓存复用。
3. **metadata 容量规格**:显式传入的 metadata 必须按 36 核槽容量分配(`16 + batch × kv_heads × 36 × 16` 个 INT32),旧长度计划需重新生成;尾部 `(36−cores)` 槽位不参与计算、不清零(靠 stride=实际核数保证不被读取)。
4. **验证覆盖缺口**:R2 未做静态 vs 动态编译产物逐位 A/B 对比(正确性以 float64 golden 判定);`core_num=28` 仅 host 容量测试覆盖,设备侧泛化采样核数为 1/2/4/8/16/24/31/32。
5. **平台能力**:实测平台 cube 32 / vector 64,接口声明 `core_num` 1~32。
6. **batch 上限**:`MAX_REQUESTS=8`(`mtgr_ragged_segment_attention_common.py:14`),即 `batch` 的 `Dim` 上界。
