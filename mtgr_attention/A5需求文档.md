## 2. 算子背景

MTGR Ragged Segment Attention 是生成式推荐（Generative Recommendation）大模型推理中的自定义掩码 Flash Attention 算子，用于 Decode/Prefill 阶段。其核心特点是：

1. **多段式掩码**：逻辑序列划分为 N 段（典型 4 段：history / context / realtime / target），每段采用不同掩码规则（Causal / Full / Diagonal），realtime 段内部可再划分为大量小子段（实测最多 1024 个小子段）
2. **Ragged Batch**：同一 batch 内各 request 长度不等，Q/K/V 采用 TND packed 布局（变长拼接）
3. **Paged KV Cache 前缀匹配**：request 命中前缀缓存时，前缀部分 KV 从 paged cache（`block_table` 索引）读取，剩余 live 部分从 packed K/V 读取
4. **GQA/MQA**：支持 `kv_group`（Q 头数 : KV 头数分组比）为 1 / 2 / 4 / 8

---

## 3. 计算描述

### 3.1 数学定义

对 batch 内每个 request `b`，每个 Q head `h`：

$$
\text{Output}[q, h, d] = \sum_k \text{Softmax}\left(\text{Mask}\left(
\frac{Q[q,h,:] \cdot K[k,h_{kv},:]^T}{\sqrt{d_{\text{head}}}}, \; \text{seg\_rules}, \text{seg\_offsets}
\right)\right) \cdot V[k, h_{kv}, d]
$$

其中 $h_{kv} = h \,/\, \text{kv\_group}$（GQA 映射），$q$ 为该 request 的 live Q 行（绝对位置从 `prefix_len` 起算），$k$ 遍历该 request 的全量 KV（前缀缓存 + live）。

### 3.2 段掩码规则

逻辑序列按 `segment_offsets[b]`（`max_segs+1` 个前缀和边界）划分为 `max_segs` 段，每段规则取自 `segment_rules[seg_id]`：

| 规则 | 含义 | Q 行可见 KV 范围 | 对角线可见 |
|------|------|------------------|-----------|
| 0 (Causal) | 下三角因果掩码 | `[0, q_pos + 1)` | 无 |
| 1 (Full) | 全可见 | `[0, seg_end)` | 无 |
| 2 (Diagonal) | 前缀可见 + 自身对角线 | `[0, seg_start)` ∪ `{q_pos}` | `q_pos`（仅自身） |

Q 行按其绝对位置二分查找（`bin_iters` 次迭代）确定所属段，进而确定掩码。

典型段结构：

```
├── history  (rule 0, causal)   ~1600-3300 tokens
├── context  (rule 1, full)        8 tokens
├── realtime (rule 2, diagonal)  ~5-700 tokens（可含最多 1024 个小子段，每段 2-50 tokens）
└── target   (rule 2, diagonal) ~1024-2100 tokens
```

## 4. 输入输出规格

### 4.1 Host 侧接口（与 A3 版本一致）

```python
def mtgr_ragged_segment_attention(
    query,                  # [total_q, heads, dim] bf16, TND packed
    key,                    # [total_q, kv_heads, dim] bf16, TND packed
    value,                  # [total_q, kv_heads, dim] bf16, TND packed
    segment_offsets_i32,    # [batch, max_segs+1] int32, 段偏移（每行前缀和，末元素=总长）
    segment_rules_i32,      # [max_segs] int32, 段规则 (0/1/2)
    q_seq_starts_i32,       # [batch+1] int32, packed Q 起始偏移（前缀和）
    matched_prefix_lens_i32,# [batch] int32, 前缀匹配长度（0 表示无前缀）
    match_mode,             # int, 0=无前缀/1=全前缀/2=混合（host 侧推导）
    key_cache,              # [num_blocks, block_N, kv_heads, dim] bf16, Paged K
    value_cache,            # [num_blocks, block_N, kv_heads, dim] bf16, Paged V
    block_table_i32,        # [batch, max_blocks] int32, 逻辑块→物理块映射
    block_size,             # int, 必须为 128
    max_request_len,        # int, 最大 request 长度
    sm_scale,               # float, attention scale（默认 1/sqrt(dim)）
    output_snd,             # [total_q, heads, dim] bf16, 输出
) -> output_snd
```

> 接口签名、参数语义、输入输出布局与 A3 版本一致；`kv_group` 由 `heads / kv_heads` 推导并校验（与 A3 wrapper 的显式 `kv_group` 可选参数保持兼容，默认 1）。

### 4.2 张量规格

| 张量 | 形状 | dtype | 语义 |
|------|------|-------|------|
| `query` | `[total_q, heads, dim]` | bf16 | packed 变长 Q（仅 live 部分） |
| `key` / `value` | `[total_q, kv_heads, dim]` | bf16 | packed 变长 live K/V |
| `segment_offsets` | `[batch, max_segs+1]` | int32 | 每 request 段边界前缀和，`[..., max_segs]` = 该 request 逻辑总长 |
| `segment_rules` | `[max_segs]` | int32 | 段规则，取值 0/1/2 |
| `q_seq_starts` | `[batch+1]` | int32 | 每 request 在 packed Q 中的起始偏移 |
| `matched_prefix_lens` | `[batch]` | int32 | 每 request 前缀匹配长度（block_N 整数倍） |
| `key_cache` / `value_cache` | `[num_blocks, block_N, kv_heads, dim]` | bf16 | Paged KV Cache 物理块池 |
| `block_table` | `[batch, max_blocks]` | int32 | request 逻辑块 → 物理块映射（仅前缀块有效） |
| `output_snd` | `[total_q, heads, dim]` | bf16 | 输出，与 `query` 同形 |
| workspace（内部） | 由实现方案定义 | bf16 | 核间交换缓冲（如需），host 侧分配 |

### 4.3 输入约束

| 约束 | 要求 |
|------|------|
| `block_size` | 必须为 128（Paged Cache 物理块大小） |
| `head_dim` (D) | 32 / 64 / 128（2 的幂） |
| `heads` (H) | 8；GQA 分组比 `kv_group = H / kv_heads` ∈ {1, 2, 4, 8} |
| `batch` | 1 ~ 8（ragged，各 request 长度可不等） |
| `max_segs` | 4 ~ 1027（realtime 子段数最多 1024） |
| `matched_prefix_lens` | 0 / 128 / 256 / 512 / 1024（block_N 整数倍） |
| 段长 | 2 ~ 3300 tokens（462 回归含 2 token 小段），非 128 对齐段长必须正确处理 |
| 累加精度 | L0C / softmax 状态 float32，I/O bf16 |

## 5. 精度要求

- 精度标准与 A3 版本一致：`atol=1e-2, rtol=1e-2`（bf16），对 `mtgr_attention/tilelang-ascend/golden.py` 中的 `golden_attention_simulated_kernel`（kernel 行为模拟）与 `golden_attention_float64`（高精度参考）双重基准
- 验收集：至少覆盖本需求第 6 节全部 7 条典型 case（含各自随机种子复测）；建议沿用 A3 交付的 462 用例全量回归体系（`testcase.py` + `run_test.py`）
- 无 INF/NAN；全 0 可见行（如纯 future 行）输出为 0（`sumexp` 下限 1 保护）
- 精度参考基线（A3 实测全量 462 用例）：RMSE ∈ [1.85e-04, 3.42e-04]，MERE ∈ [6.18e-03, 7.63e-03]

---

## 6. 性能需求（验收核心）

### 6.1 测量口径

| 项 | 定义 |
|----|------|
| 指标 | **Kernel 纯算子耗时**（msprof op 采集，排除 launch / 框架开销） |
| 方法 | Warmup 5 次，Repeat 5 次取平均（与 A3 基线采集方式一致） |
| A3 基线 | A3（`910_9382`，24 核）实测数据，取自 `results/compare_results.csv` 的 `sparse_kernel_avg` 列 |
| 目标 | **每条 case 均需满足：A5 kernel 耗时 ≤ A3 kernel 耗时 / 3（加速比 ≥ 3.0x）** |
