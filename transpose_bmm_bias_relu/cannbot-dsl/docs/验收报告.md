## 1. 算子概述

将网络中固定子图 `Transpose1 → BMM(+bias) → Transpose2 → ReLU` 融合为**单个 kernel**,消除两次纯搬数 Transpose 与逐元素 ReLU 的独立访存及 3 次 kernel 启动/调度开销。

**计算公式**:

```
out[i, b, j] = ReLU( Σ_c A[i, b, c] · B[b, c, j] + bias[b, j] )
```

**接口**:`transpose_bmm_bias_relu(a, b, bias, transpose_b=False) -> Tensor`

| 张量 | dtype | shape | 说明 |
|---|---|---|---|
| A | FP16 / BF16 | `[m, batch, k]` | 激活输入,ND 连续;Transpose1 已融合(零拷贝 stride 视图绑定) |
| B | FP16 / BF16 | `[batch, k, n]`;`transpose_b=True` 时为 `[batch, n, k]` | 批量权重,双 layout 以编译期属性区分 |
| bias | FP16 / BF16 | `[batch, 1, n]` | 沿 m 维广播 |
| 输出 | 同输入 | `[m, batch, n]` | Transpose2 + ReLU 已融合 |

**动态维**:`m`、`batch`、`k`、`n` 全部运行时动态(`Dim(min=1)`),一次编译泛化所有 shape;`transpose_b` 与 dtype 为编译期常量,每种组合进程内编译一次(`lru_cache`,共 4 个程序)。物理 tile 固定:BASE_M=128、BASE_N=256、BASE_K=64;M 尾块按 16 对齐静态展开 8 桶,运行时选最小覆盖桶。退化维度(m/n/batch/k = 0)由 host 侧 torch 回退,不进 kernel。

**实现方式**:cannbot-dsl(Cube kernel,L1/L0A/L0B/L0C RingBuffer 双缓冲,bias 经 BIAS buffer 融入 MMAD epilogue,ReLU 在 L0C→GM 回写路径完成;N 维双 tile 分组共享 A window 提升 L1 复用)。

## 5. 性能验收 ✅

**判据**:融合算子耗时 ≤ BMM 单算子 + 0.2 × (Transpose1 + Transpose2);README 绝对目标 m=85 时 ≤ 66 us。

**测量方法**:torch_npu.profiler(msprof)`kernel_details.csv` 纯设备 kernel 耗时,20 次 warmup 后取 100 次迭代均值;分立组件(T1/BMM/T2/ReLU)以 torch 原生算子同口径单测。fp16,batch=8,k=n=2048,单位 us:

| m | 融合(正常B) | 融合(转置B) | T1 | BMM | T2 | ReLU | 分立合计 | 阈值 | 判定 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | **16.27** | 16.09 | 0 ¹ | 17.60 | 0 ¹ | 1.05 | 18.65 | 17.60 | ✅ |
| 32 | **17.67** | 16.92 | 5.83 | 24.94 | 5.43 | 2.51 | 38.71 | 27.20 | ✅ |
| 41 | **18.32** | 17.24 | 5.95 | 25.27 | 5.92 | 2.59 | 39.72 | 27.64 | ✅ |
| 50 | **17.47** | 17.86 | 6.78 | 25.68 | 6.43 | 2.64 | 41.53 | 28.32 | ✅ |
| 85 | **20.45** | 20.85 | 8.26 | 29.04 | 8.10 | 3.10 | 48.50 | 32.31 | ✅ |

¹ m=1 时 torch `transpose(0,1).contiguous()` 因 size-1 维已满足连续布局为 no-op、不发射 kernel,阈值退化为最严格口径(纯 BMM);融合算子(16.27)仍快于 baddbmm 本身(17.60)。

- **m=85 对照绝对目标 ≤66 us:实测 20.45 us,余量 3.2×**(本机整体快于原始 profiling 环境:同机 BMM 29.04 vs 原表格 61;相对判据在两种口径下均满足)。
- 相对分立基线加速比:m=85 **2.4×**、m=50 **2.3×**、m=41 **2.2×**、m=32 **2.2×**、m=1 1.15×。
- 两种 B layout 性能对称,差异 <5%。
- 稳定性:m=85 融合 kernel 100 次迭代 min/p50/max = 19.9/20.6/22.7 us。

## 6. 精度验收 ✅

**判据**:与分立算子基线(Transpose + BatchMatMul + BiasAdd + ReLU)对齐;对照 CPU FP32 golden(`einsum("mbk,bkn->mbn")` fp32 累加、末端单次 cast),`torch.testing.assert_close(atol=0.002, rtol=0.002(fp16)/0.02(bf16))`。

**覆盖**:2 dtype × 5 个 P0 m × 2 layout = 20 组,全部 PASS。

| dtype | max_abs vs CPU-fp32 golden | max_abs vs 分立基线(NPU) | 判定 |
|---|---|---|---|
| fp16 | ≤ 0.0078(≈1 ulp @1.0) | ≤ 0.0078 | ✅ 10/10 |
| bf16 | ≤ 0.0313(≈1 ulp) | ≤ 0.0625(≈1–2 ulp) | ✅ 10/10 |

误差均在对应 dtype 表示精度量级内,与分立算子基线一致,无系统性偏差。

## 7. 已知限制与集成建议

1. **host 提交开销(P0 级集成注意事项)**:Python DSL 入口每次调用 host 侧开销约 350 us(动态 shape 参数编排/launch 路径),朴素循环下端到端 wall time 为 host-bound(~280–390 us/call),**远大于 kernel 本身的 ~20 us**。验收判据针对算子 kernel 耗时(已达标);端到端收益落地建议任选其一:
   - **aclnn C API**:源仓库已附带预编译 `libtranspose_bmm_bias_relu_aclnn.so` + ascend950 kernel 二进制,C++ 侧 launch 开销 us 级;
   - **torch_npu 图捕获**(graph capture)消除逐次 Python 提交;
   - 作为大图子图被调度,摊薄提交开销。
2. **编译时间**:每个 dtype × transpose_b 组合首次 JIT 编译约 60 s(进程内缓存复用);对冷启动敏感的场景建议走 aclnn 预编译产物。
3. **输入约束**:三输入须同 dtype(FP16/BF16)、同设备、rank-3、ND 连续存储;`bias` 第二维必须为 1。
4. **退化维度**:m/n/batch/k 任一为 0 时走 host torch 回退路径(语义正确,非 kernel)。
